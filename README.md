# Pixel Perfect Page

Промт для Lovable: Image-to-Interactive-Page сервис

Скопируй весь текст ниже и вставь одним сообщением в чат Lovable, когда создаёшь новый проект.

ПРОМТ (копировать с этой строки)

Собери веб-сервис "Image to Interactive Page". Пользователь загружает скриншот сайта или дизайн-макета, сервис анализирует его через Claude API (с vision) и генерирует максимально точную визуальную копию в виде рабочей HTML/CSS/JS страницы с реально функционирующими интерактивными элементами.

1. Технологический стек

Frontend: React + Tailwind

Backend: Supabase (используй нативную интеграцию Lovable с Supabase)

Хранение файлов: Supabase Storage (bucket для загруженных изображений)

База данных: Supabase Postgres

Логика вызова AI: Supabase Edge Function (Deno), чтобы API-ключ Anthropic никогда не попадал в клиентский код — храни его в Supabase Secrets

Аутентификация: Supabase Auth (email/password + возможность анонимного использования с лимитом в 3 генерации)

2. Структура базы данных

Создай таблицы:

projects

id (uuid, pk)

user_id (uuid, fk на auth.users)

source_image_url (text) — ссылка на загруженный скриншот в Storage

title (text)

status (text: 'processing' | 'completed' | 'failed')

generated_html (text) — итоговый код страницы

component_map (jsonb) — структурированное описание найденных компонентов

created_at (timestamptz)

generation_logs

id (uuid, pk)

project_id (uuid, fk)

step (text) — этап пайплайна

status (text)

error_message (text, nullable)

created_at (timestamptz)

Включи Row Level Security: пользователь видит и редактирует только свои projects.

3. Основной флоу приложения

Экран 1 — Загрузка

Drag-and-drop зона для изображения (PNG/JPG, до 10 МБ)

После загрузки — превью картинки и кнопка "Сгенерировать интерактивную страницу"

Индикатор прогресса с этапами: "Анализирую макет" → "Распознаю компоненты" → "Пишу код" → "Собираю интерактив" → "Готово"

Экран 2 — Результат

Слева: split-view с оригинальным изображением

Справа: живой iframe-превью сгенерированной страницы (реально кликабельной)

Переключатель "Оригинал / Результат / Рядом"

Кнопка "Скачать код" (экспорт .html файла)

Кнопка "Редактировать" — открывает чат, где пользователь текстом просит поправить конкретный элемент ("сделай кнопку получить расчёт розовой", "аккордеон FAQ должен открываться плавнее") — это должно вызывать повторный запрос к Edge Function с уточняющим промтом и текущим кодом на входе

Экран 3 — Мои проекты

Список всех сгенерированных страниц пользователя с превью-скриншотами и датой

4. Edge Function: generate-page

Создай Supabase Edge Function generate-page, которая:

Принимает image_url (или base64) и опционально previous_html + edit_instruction для режима правок

Кодирует изображение в base64, если оно ещё не в этом формате

Отправляет запрос к Anthropic API (https://api.anthropic.com/v1/messages) с моделью claude-sonnet-5 (актуальную модель уточни в документации docs.claude.com на момент разработки — названия моделей могут обновляться), передавая изображение как image content block

Использует системный промт (см. ниже)

Парсит ответ, вырезает код между тегами <final_code> и сохраняет его в поле generated_html таблицы projects

Обновляет status на completed, логирует каждый шаг в generation_logs

Возвращает готовый HTML клиенту

5. Системный промт для вызова Claude API (зашей его в Edge Function как system-параметр)

Ты — эксперт по фронтенд-разработке и точному воссозданию веб-дизайна по изображению.

Тебе дан скриншот веб-страницы. Твоя задача — воссоздать её максимально точно как единый самодостаточный HTML-файл с inline CSS (в тегах <style>) и inline JS (в тегах <script>), используя Tailwind CDN для утилитарных классов, где это ускоряет работу.

ТРЕБОВАНИЯ К ТОЧНОСТИ:
- Сохрани точную структуру блоков сверху вниз, как на изображении
- Определи цветовую палитру по пикселям изображения (основной, акцентный, фоновый цвета) и используй именно её через CSS-переменные в :root
- Определи по засечкам/пропорциям шрифт (sans-serif гротеск / с засечками) и подбери ближайший доступный веб-шрифт (Google Fonts), сохрани относительные размеры заголовков и текста
- Сохрани пропорции колонок, отступы между секциями, скругления углов карточек и кнопок
- Для фотографий и иллюстраций, которые невозможно воспроизвести точно, используй смысловые SVG-плейсхолдеры или градиентные заглушки в похожей цветовой гамме — никогда не оставляй пустые области

ТРЕБОВАНИЯ К ИНТЕРАКТИВНОСТИ (это критично, элементы должны РЕАЛЬНО РАБОТАТЬ, не просто визуально дублировать):
- Аккордеоны (FAQ и подобное) — клик разворачивает/сворачивает контент с плавной CSS-анимацией высоты, иконка +/– меняется на -/×
- Табы — переключение контента без перезагрузки, активный таб визуально выделен
- Слайдеры/карусели (отзывы, кейсы) — работают стрелками и точками-индикаторами, автоматически листаются каждые 5 секунд с паузой при наведении
- Выпадающие меню в навигации — открываются по клику/hover, закрываются по клику вне области
- Формы — с client-side валидацией обязательных полей (подсветка красным при пустом поле), при отправке показывают сообщение об успехе без реальной отправки на сервер (это демо)
- Sticky-хедер — остаётся видимым при скролле, может менять фон при скролле вниз
- Hover-состояния — на всех кнопках, карточках, ссылках должны быть плавные transition-эффекты (transform, box-shadow, цвет)
- Плавный скролл (scroll-behavior: smooth) к якорям меню
- Мобильная адаптивность — гамбургер-меню на узких экранах, сетки перестраиваются в колонку

Если тебе передан previous_html и edit_instruction — не переписывай всё с нуля, внеси точечное изменение, сохранив всю остальную структуру и код без изменений.

Сначала внутри тегов <analysis> кратко перечисли, какие блоки и интерактивные компоненты ты обнаружил на изображении.

Затем выведи ПОЛНЫЙ финальный код внутри тегов <final_code>. Это должен быть валидный самодостаточный HTML-документ, готовый к рендеру в iframe без внешних зависимостей, кроме Tailwind CDN и Google Fonts CDN.
